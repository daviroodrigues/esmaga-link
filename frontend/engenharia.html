3. Por que rejeitar abordagens convencionais

Comparativo prático entre estratégias comuns de geração de chaves em encurtadores distribuídos.

Comparativo técnico de estratégias de geração de códigos
Abordagem Complexidade Colisões Ofuscação Trade-off estrutural
AUTO_INCREMENT O(1) Zero Nenhuma Contenção central e enumeração trivial de volume de negócio
UUID v4 O(1) Praticamente nula Alta 128 bits (longo demais para links curtos) e fragmentação de índice
Hash truncado / NanoID O(1) Possíveis Alta Paradoxo do Aniversário exige SELECT before INSERT e retentativas
Esmaga Link (Hull-Dobell + Base62) O(log n) Zero (prova algébrica) Alta (2 camadas) Aritmética pura em CPU com lotes no Redis e escala horizontal stateless

4. Arquitetura para alta vazão

Isolamento estrito entre o caminho crítico de redirecionamento e a ingestão de telemetria (CQRS).

Hot Path (P99 < 50ms)

Redirecionamentos 302 resolvidos em cache L1 (memória) e L2 (Redis), com fallback durável no Cassandra e invalidação via Pub/Sub.

Batch Leasing stateless

Cada instância reserva lotes de IDs no Redis via INCRBY, embaralha o lote localmente e grava checkpoints no Cassandra para recuperação segura.

Telemetria assíncrona

Cliques são publicados no RabbitMQ sem bloquear o redirecionamento e processados em background por workers dedicados para o painel analítico.
